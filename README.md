# CYBER CORE

Первый полностью рабочий вариант оригинального desktop-кликера на Python / PyQt6.
Ядро, орбиты, свечение и эффекты нарисованы QPainter: внешних изображений, старого
кода проекта и готовых шаблонов кликеров нет.

</div>

## Быстрый запуск на Windows

Требуется Python 3.11 или новее, рекомендуется 64-битная версия.
Распакуйте архив и откройте PowerShell в папке `cyber-core`, где лежит `main.py`.

```powershell
py -3 -m venv .venv
-m pip install -r requirements.txt
python main.py
```

## На Linux:
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python3 main.py
```

Активация окружения не нужна: команды используют его интерпретатор напрямую.
Если команда `py` отсутствует, установите Python с python.org и включите Python
Launcher, либо замените `py -3` на `python`, если он уже доступен в PATH.

Единственная runtime-зависимость: `PyQt6>=6.7,<7`.
Стандартная библиотека обеспечивает JSON, Decimal и тесты; pytest не нужен.

Без параметра используется пользовательская `AppLocalDataLocation` Qt с подпапкой
`saves`, обычно `%LOCALAPPDATA%\CyberCore\CyberCore\saves` на Windows.
Точный путь отображается во всплывающей подсказке статуса сохранения внизу окна.
Не используйте одну папку для одновременных сессий: приложение блокирует её через
QLockFile и освобождает при выходе.

## Как играть

1. Нажимайте на светящееся ядро. Начальная сила импульса — **1 EN**.
2. За **25 EN** купите импульсный усилитель. Каждый его уровень даёт **+1 EN/клик**.
3. Когда общий заработок достигает **50 EN**, открывается автономный реактор.
4. Первый реактор стоит **80 EN**, каждый уровень добавляет **+2 EN/с**.
5. Повышайте уровни обеих технологий. Покупки уменьшают баланс, но не общий заработок.

Ядро поддерживает мышь, пробел и Enter, когда имеет клавиатурный фокус.
Tab переключает фокус; удержание клавиши не порождает автоповтор импульсов.
Недоступные покупки отключены с пояснением: закрытая технология, недостаток EN
или максимальный уровень. При успешной покупке отображается новый уровень.

Флажок «Уменьшить анимацию» останавливает вращение, пульсацию и перемещение
всплывающих чисел. Краткий статичный отклик клика сохраняется.
Настройка восстанавливается после перезапуска.

Широкое окно: ядро и магазин рядом. При ширине менее 1000 px панели становятся
вертикальными; недостающая высота доступна прокруткой. Минимальный размер 720×640.
Цифры K/M/B/... — компактное отображение. Оно не используется в расчётах;
точные баланс и цены доступны в подсказках.

## Экономика версии 1.0

Пусть `L` — текущий уровень перед покупкой, начиная с 0:

| Технология | Цена следующего уровня | Эффект уровня | Условие открытия |
| --- | --- | --- | --- |
| Импульсный усилитель | ceil(25 × 1.45^L) | +1 EN/клик | Сразу |
| Автономный реактор | ceil(80 × 1.55^L) | +2 EN/с | Общий заработок ≥ 50 EN |

Начальная сила клика = 1; начальная автодобыча = 0.
Цена округляется **вверх** до целого EN. Добыча может быть дробной.
Ресурсы используют `Decimal` с точностью 80 цифр, а не двоичный float.

Каждая технология имеет предел 200 уровней. Предел ресурсов/общего заработка —
10^60 EN; предел кликов — 10^15. Эти явно заданные границы предотвращают
переполнение и делают формат сохранений проверяемым.

Автодобыча использует монотонное реальное время, а не количество кадров. При
покупке сначала начисляется прошедшая добыча по **старой** скорости, после чего
применяется улучшение. Таймер интерфейса обновляет данные раз в 100 мс;
визуальные эффекты работают отдельно примерно на 30 кадрах/с.

**Офлайн-добычи в этой версии нет:** после закрытия игры энергия не начисляется.
Минимизация открытой игры не отключает игровой таймер.

## Структура и границы ответственности

```text
cyber-core/
├── main.py                    # QApplication, пути, блокировка, загрузка
├── game_state.py              # Состояние, экономика, действия, проверка JSON
├── requirements.txt
├── README.md
├── DEVELOPMENT.md
├── TESTING.md
├── systems/
│   ├── __init__.py
│   ├── upgrades.py             # Неизменяемые определения технологий и цены
│   └── persistence.py          # Атомарная запись, резервная копия, восстановление
├── ui/
│   ├── __init__.py
│   ├── core_widget.py          # QPainter, ввод, анимация, всплывающие числа
│   ├── formatting.py           # Только форматирование отображения
│   └── main_window.py          # Компоновка, таймеры, вызовы модели, диалоги
└── tests/
    ├── __init__.py
    ├── test_game.py
    ├── test_persistence.py
    ├── test_ui.py
    └── smoke_app.py            # Настоящий запуск и игровой цикл через event loop
```

Папка `assets/` не нужна: графика полностью процедурная. Папка `saves/`
создаётся при запуске в пользовательском каталоге или в явно выбранном месте.
В архиве нет чужих сохранений и виртуального окружения.

`GameState` не зависит от Qt. Все игровые значения рассчитываются здесь или
в каталоге технологий. UI только передаёт действия и время, форматирует результат
и показывает эффекты. `ActionResult` сообщает об успехе, причине отказа и сумме.

## Сохранения и восстановление

- JSON содержит версию, баланс, общий заработок, силу клика, автодобычу, уровни,
  количество кликов и настройки. Decimal хранится строками без потери точности.
- Сила клика и автодобыча вычисляются из уровней. При загрузке сохранённые значения
  сверяются с вычисленными, чтобы не допустить рассинхронизации.
- Автосохранение — каждые 15 секунд; есть ручная кнопка и сохранение при закрытии.
- Сначала записывается временный файл в той же папке, выполняется `flush`/`fsync`,
  затем `os.replace`. Это уменьшает риск получить половину JSON при прерывании записи.
- `save.backup.json` содержит предыдущую валидную запись основного сохранения.
- Если основной файл повреждён, проверяется резервная копия. Игрок получает
  предупреждение: прогресс из более поздней записи мог быть потерян.
- Если восстановить нечего, предлагается новая сессия **без записи**. Имеющиеся
  файлы не перезаписываются, пока пользователь не подтвердит разрешение.
- После подтверждения повреждённый файл копируется в уникальный
  `.invalid-<UTC-время>-<идентификатор>.json` до перезаписи. Ошибка копирования
  запрещает запись, а не уничтожает исходный файл.
- Отказ оставляет сессию только в памяти. При выходе игра дополнительно спрашивает,
  можно ли потерять несохранённые изменения этой сессии.
- Ошибки доступа/диска отображаются. Если сохранение при закрытии не удалось,
  можно отменить выход. Повторяющиеся одинаковые ошибки автосохранения не создают
  диалог каждые 15 секунд, но статус остаётся ошибочным.
- Неизвестная версия, NaN/Infinity, отрицательные значения, неправильные типы,
  несовпадающие параметры и файлы больше 1 MiB считаются некорректными.

Для ручного восстановления сначала закройте игру. Сделайте отдельную копию всей
папки сохранений; затем можно скопировать валидный `save.backup.json` в `save.json`.
Архивы `.invalid-…json` автоматически не удаляются.

Атомарная замена не является абсолютной гарантией при поломке диска или отключении
питания. Для долгосрочного хранения сохраняйте внешнюю копию папки.

## Проверки на Windows

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe tests\smoke_app.py
```
## Проверки на Linux

```bash
./.venv/bin/python -m unittest discover -v
./.venv/bin/python tests/smoke_app.py
```

UI-тесты выбирают `QT_QPA_PLATFORM=offscreen`, если платформа не задана явно.
Тесты используют временные папки и не изменяют игровые сохранения пользователя.
Подробности реально выполненных проверок и ограничения — в `TESTING.md`.

## Необязательная сборка EXE на Windows

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --windowed --onedir --name CyberCore main.py
.\dist\CyberCore\CyberCore.exe
```

## Сборка приложения для Ubuntu, Debian или Linux Mint:

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
```

Создайте виртуальное окружение и установите зависимости:

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
```

После этого начните делать сборку приложения:

```bash
pyinstaller --noconfirm --clean --windowed \
  --name CyberCore \
  --collect-all PyQt6 \
  main.py
```

Для передачи игры понадобится **вся** папка `dist\CyberCore`, не только EXE.
Эта сборка предложена как инструкция, но не выполнена и не проверена на Windows и Linux.
Перед распространением проверьте лицензионные требования PyQt6/Qt.
